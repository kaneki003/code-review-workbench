### Model changes while work is running

An attempt keeps its model fixed through all its model/tool steps. When idle, a selector change applies to the next question or automatic investigation. If an attempt is active, save the new selection for the next attempt and show both the running model and "Next: <selected model>"; do not cancel work or change models midway through an answer. Resolve the selected model at actual dispatch, so queued questions use the then-current deliberate selection, and store the resulting configuration with each attempt. A staged preference is distinct from the running attempt's active configuration; it does not invalidate the old attempt merely by being staged.

To apply the selection to the current question, the reviewer uses Stop followed by Retry with the new model after the owned work settles. Retain the stopped prefix and the single original question. Never automatically rerun a command or an uncertain side effect because the model changed. A pending model change does not override Stop, source/account/provider fences or execution-recovery rules. This makes model switching available during review without combining two models' output into one attempt or losing useful work.

## Stop, Retry and late results

Stop immediately blocks further model/tool dispatch, freezes the displayed partial answer, propagates cancellation to the stream and owned execution, and flushes the retained prefix. Show Stopping until the local work's outcome is established; failed termination, crash or uncertain descendants remain unknown. A provider may continue computation or charge after the client aborts. Do not promise that Stop eliminates provider-side work/cost or undoes source changes already made.

Retry creates a new attempt under the original user turn. Retain the failed/stopped partial attempt; the visible question and preceding conversation remain single. Set explicit request timeouts and disable hidden SDK generation retries (`maxRetries: 0`) initially. A new attempt can reuse attributed known tool outcomes; never silently re-execute an operation whose effect is unknown. Resolve uncertain commands before conflicting work. Retrying model text does not resume a background process or authorize a GitHub mutation.

Before each tool dispatch/result commit, revalidate identities, ownership, clear/source/active-configuration and permission generations. After a PR/account/provider/key change or an applied model change between attempts, an old event cannot update the new active answer, examination scope or suggestions. Merely staging the next model leaves the current attempt's model/configuration valid until it finishes or stops. Persist known old command effects against their original attempt when recovery requires it; ignoring stale presentation does not establish process termination. Source Sync waits for workbench checks to finish or be confirmed stopped. Model-only work is cancelled/fenced at the source transition; partial older answers retain their original source and stale status. Discussion refresh remains independent and can flag an answer based on superseded discussion without performing source Sync.

Clearing private data invalidates all old generations and projections, follows the accepted deletion/backup protocol, and starts fresh model context. Late streams cannot repopulate cleared content. A restarted host restores saved work and labels unfinished attempts interrupted/unknown; it never automatically regenerates, runs a command or replays a publication operation.

Do not create an extra approval rule just because a normal requested command writes reviewed files or generated output. Keep autonomous fixing outside this workflow.

Revalidate grants immediately before launch. Revocation fences queued dispatch and requests Stop for affected running work; a previously launched process does not magically lose its rights, and completed writes are not undone. End review-scoped grants on Exit Review; do not silently broaden them to another review. Unknown execution must be reconciled before a conflicting check or source transition. Filesystem sandbox rights are not proof that a script is useful, benign or a correct test.

## Offline command execution

Use an identifiable owned terminal projection, implemented initially with MXC `spawn` pipes and VS Code Pseudoterminal, plus conversation tool activity. Do not write into an existing user terminal, occupied or idle. A projected terminal is a display for a managed noninteractive check, not a general interactive shell. Commands requiring user input explain that limitation and offer manual execution.

The execution interface takes validated executable, argv, cwd, task/source identity and policy. MXC takes a command string: pass a fixed packaged launcher and send structured invocation data over stdin, with argument-preserving process launch inside containment. Do not concatenate model-provided text into shell code. Prove Windows wrapper/batch and adversarial argument handling. Source/check output includes the real working directory, source fingerprint, exit/error/interruption/unknown state, output completeness and local-versus-CI distinction.

Give contained commands narrowly scoped project read/write, per-run clean home/scratch and read-only required tool installations. Construct a minimal environment; exclude provider/GitHub keys, agent sockets, editor IPC, credential helpers, startup/preload settings, user proxies and the private state root. Deny external network and host loopback/control access. Establish socket/named-pipe isolation as a capability gate before enabling execution; no universal MXC named-pipe-deny API is assumed. An allowed workspace may itself contain secrets; this is not a sensitive-file exclusion or secret-scanning feature.

| Host | Initial owned-command prerequisite/limit |
| --- | --- |
| macOS | macOS 15+ with validated Seatbelt containment; disable GUI/Keychain access, external IP networking and host localhost. Local-server tests can fail and remain manual. Writable directories must not expose a host Unix-socket broker. |
| Linux | Selected VS Code prerequisites, bubblewrap >=0.5.0 and enabled unprivileged user namespaces. Offline private loopback can support services inside the same isolated execution, not existing host services. |
| Windows | Windows 11 serviced builds meeting MXC's published table: 24H2 26100.9278+, 25H2 26200.9278+, 26H2 26300.9550+, or 26H1 28000.2804+, plus the Node stdio gate. Probe the actual requested containment capabilities. |

On Windows, do not enable a configuration that can silently fall back to changing host ACLs. The raw MXC schema exposes this fallback, but the public V1 request does not expose its disabling switch. Before enabling Windows commands, prove the intended non-mutating tier can be selected/enforced through the pinned supported interface; otherwise keep that capability unavailable and return the precise interface gap for decision. A post-launch warning is not sufficient protection. Do not patch undocumented internals or claim a version probe alone proves the policy.

Offline networking does not itself block credential brokers/IPC: validate those paths as well as IPv4/IPv6. Deny unsupported policy requests, with no automatic host/unsandboxed fallback. Keep explicit human GitHub actions online in the separate host connection. The owner accepted manual network/setup/local-server commands as the first-release exception; that does not give the model a general online shell. Further online command containment requires a separate deliberate design.

## Initial processing bounds

The owner accepted the limits below as adjustable starting implementation settings. The investigation, input, visible-answer and command bounds were explicitly reviewed; the supporting paging, connection and extraction parameters belong to the accepted combined contract and remain subject to measured tuning. These are not benchmark results or new product quality gates. Preserve the accepted storage ceilings: one input up to 1 MiB UTF-8, raw attachment up to 10 MiB and captured text up to 1 MiB per tool activity. Oversize/failed imports are not accepted as saved truncated originals.

| Work | Starting bound and behavior |
| --- | --- |
| Model input | Target at most 64,000 input tokens, additionally capped below the selected model's effective context after output/thinking reserves. Use provider counting where available and conservative validated estimates otherwise. Compact before dispatch and handle provider limit errors honestly. |
| Model output | For every connection, stop the attempt when retained visible answer text reaches 64 KiB UTF-8, retaining a complete-code-point prefix and marking it partial. For the parallel API path, additionally use at most 8,000 tokens per model step where the model supports that parameter. Direct ChatGPT-plan HTTP does not accept `max_output_tokens`. Bound streamed event buffers at 1 MiB and assembled arguments at 64 KiB per tool call before dispatch; malformed or oversize requests fail without execution. Host cancellation is not a hard server-side output/thinking or charged-token cap. A limit or local cancellation is partial; offer deliberate continuation. |
| Investigation | At most 8 model requests, 16 tool calls and 5 minutes of active work. Count any model-assisted context summaries within the request budget; do not create a hidden unbounded preparation loop. Pause/mark partial at a bound with useful work retained; user can choose Continue as another attempt under the same request/question. Time waiting for an approval is separate. |
| Provider connection | 30-second connection/first-event target, 90-second idle timeout, bounded total attempt time above. A timeout is a client outcome, not proof of zero provider work/cost. |
| Source tools | Up to 64 KiB text per read page; 100 search matches/page with continuation and actual completeness. Large/binary/unavailable files get explicit limits and narrower follow-up reads. |
| Attachments | Extract/consider at most 256 KiB text per document pass and at most 200 PDF pages per extraction pass, with additional pages/passes on demand. Limit an extraction worker to 30 seconds per pass; preserve available text and report incomplete extraction. |
| Commands | One at a time; initial 2-minute timeout, explicit longer rerun when useful. Capture at most 1 MiB of combined output per activity; continue draining safely after the capture bound and label omitted output. No unbounded hidden raw log. |

Compaction keeps the complete canonical local conversation. Prioritize the current question, effective instructions, explicit same-PR decisions, recent complete tool groups, active/dismissed concerns and current evidence; replace older input with a summary carrying source references and omissions. Never split a function call/result group or silently delete a human decision to fit. Summaries are attributed derived material and can be wrong/stale. When essential current input cannot fit, explain the limit and ask for a narrower question instead of silently dropping it. No model-specific opaque compaction state is transferred across providers.

At a limit, show what was and was not examined. Continue is a capacity control, not a requirement to finish a review, run tests or resolve every suggestion. Do not invent a universal maximum PR file count: large/mixed-language PRs remain navigable with incremental AI scope and explicit partial results. Usage displays provider-reported counts when available; absent interrupted usage/cost stays unknown, with provider billing links rather than invented exact prices or app-paid credit.

## Required implementation validation

For each account connection before it is enabled, establish its permitted use and validate real sign-in, inference permission, plan/model access, usage failures, refresh/revocation and credential ownership through that route. The selected interim integration is direct ChatGPT-plan requests on the personal-local assumption; proprietary-product answers are later public-release gates and do not block the scoped planning/handoff. Validate the exact direct request/tool format, terminal events, app-owned token lifecycle, model catalog, input estimates and host-side cancellation limits. Public ChatGPT/Gemini account support still requires the provider eligibility answers and release reconciliation. The API-only fixtures below do not satisfy those account gates. Use synthetic repositories/text and explicit owner-authorized provider access later. No credentials, inference, provider calls or sandbox workloads were exercised for this plan. Required gates:

1. Resolve/pin the registry-checked dependencies with pnpm, package native MXC assets/notices and load them in installed VSIX files on the actual minimum/current VS Code/Node/OS matrix. Test ESM/CommonJS and native dependency loading; unsupported cells remain unadvertised.
2. For both providers, verify key/model access, streamed text, tool argument assembly, function/result round trips, schema-constrained suggestions and refusal/limit finishes. Round-trip provider metadata through database save/restart. Preserve gateway/direct-endpoint separation.
3. Inject invalid/revoked keys, model denial, quota/billing/rate errors, disconnection before/after text and context overflow. Assert one user turn, retained partial attempts, bounded requests and no silent provider/model/billing fallback or unsafe repeated tool action.
4. Stop during text, argument assembly, approval, spawn and output. Test child detachment/process groups, host crash/restart and termination failure. Establish which descendants are controlled; show unknown when settlement cannot be established and keep source Sync blocked where necessary.
5. Exercise PR/account/provider/key/model changes, guidance/discussion/source changes, clear versus pending streams, restart and stale callbacks. Include voluntary model changes with no access failure, idle and in-flight selection, queued questions, Stop/Retry with the new model and model removal from the refreshed catalog. Assert original model attribution, visible running/next labels, preserved same-PR conversation, correct fences and no resurrection or cross-review content transfer.
6. Test exact-revision reads/search, mutable-worktree checks, renamed/deleted/local source, explicit-only related PRs, guidance precedence, malformed/oversize messages, partial PDFs and worker timeouts. Validate citations, exposed omissions, bounded context and protected decisions/tool groups.
7. Test reviewer-paced orientation/suggestions, underlying-concern merges, existing discussion links, dismissal persistence and meaningful resurfacing through Sync. No AI activity sets a human Reviewed mark or certifies unexamined code.
8. Probe each actual command request. Test path/symlink escapes, Unix sockets/named pipes, Keychain/editor/credential brokers, startup configuration, IPv4/IPv6 and host localhost; verify no provider/GitHub keys reach the child. Resolve Windows ACL fallback before enabling that cell. A failed boundary disables execution rather than weakening it.
9. Verify normal user terminals stay untouched, noninteractive failures explain recovery, source-changing checks follow the same policy, grants are visible/revocable, revocation races stop queued work and partial output survives terminal/view closure. Manual network checks are explicitly outside owned execution; do not invent captured evidence from them.

Measure responsiveness, memory, extraction cost and useful context on small/large/mixed-language fixtures, then tune the starting bounds with recorded evidence. No passing quality benchmark is claimed today. A dependency/platform/policy failure that changes the selected contract returns for decision; it does not authorize a silent provider replacement, unrestricted shell or weakened publication boundary.
