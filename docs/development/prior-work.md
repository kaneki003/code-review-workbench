# Preserve prior work during PR review

Implementation for [issue #23](https://github.com/kaneki003/code-review-workbench/issues/23), awaiting owner review in [draft PR #36](https://github.com/kaneki003/code-review-workbench/pull/36). Enter/Exit preserve supported prior work and reconcile interrupted preservation, restoration and artifact cleanup. Platform CI acceptance remains unresolved. The owner requested finishing the implementation before resolving CI; this document does not claim platform acceptance or ticket closure.

## Walk through the change

1. **Record saved work before Git changes it.** The existing native editor adapter saves normally and captures the original tabs. [ReviewManager](../../src/application/review-manager.ts) then starts a durable checkout intent. [WorkManifest](../../src/application/prior-work.ts) records index entries separately from saved disk content, including missing paths and nonignored new files. Each content identity is a Git blob hash of the actual bytes. This distinguishes staged and unstaged changes on one file without making unfinished work reviewable source.
2. **Prove the exact backup before checkout.** [prior-work.ts](../../src/connections/prior-work.ts) inventories supported representations. [store-worker.ts](../../src/connections/store-worker.ts) records the original HEAD, prior stash observation and unique marker before the typed `stash push --include-untracked` operation. The existing guarded process/journal protocol records child identity and outcome. The verifier compares the stash's index, tracked-content and new-file trees with the manifest, then pins that exact object under `refs/code-review-workbench/recovery/<stash operation ID>/prior-work`. A Git reference keeps the object reachable even if the ordinary stash list changes. Checkout follows the acknowledged pin and clean original facts.
3. **Verify restoration before completion.** Exit restores the original branch/commit using the existing protected checkout, then applies the exact object with `stash apply --index`. It verifies the disk/index manifest before restoring editors and recording completion. A refused checkout can automatically restore prior work when the actual original checkout is still safe. Interrupted stash/apply operations reconcile real files, objects, reflog markers and receipts; recovery never assumes the latest stash belongs to the workbench or repeats an uncertain apply.
4. **Retry only proven nonexecution.** Recovery can use a fresh operation identity when matching durable receipts and actual files prove the previous attempt did nothing, or a prepared intent proves its Git child was never armed. An uncertain or partially applied stash cannot be replayed. Fresh checkout attempts keep their earlier identities for owned-artifact cleanup. There are at most 32 such attempts; beyond that, recovery offers explicit restoration.
5. **Release only proven owned protection.** After the original manifest, native editors and completion receipt are verified, cleanup compares each owned reference with its expected object and matching operation receipts. It removes unchanged original/prior-work pins and eligible merged review branches. Moved, unproven or unmerged references remain and are named in the result. The ordinary operation-tagged stash remains as a named backup; cleanup never drops a shifting stash ordinal. Exit reports whether that exact object is still in the stash list, including when another writer has removed it.

No new framework is introduced. The existing SQLite worker, independent recovery journal, native process guard, expected-value reference writes and native editor adapter carry the new steps. A clean starting checkout still uses the existing path and creates no stash. Committed diffs and drafts retain their original exact-source identities.

## Git attributes and line endings

Ordinary `.gitattributes` text/binary and LF/CRLF rules now use Git's effective per-path attributes instead of a presence-based refusal. This includes nested overrides, repository `info/attributes`, a configured attributes file and default user/system attributes under the existing restricted Git environment. The same checks inspect the PR's committed attributes before preservation or checkout. Custom content filters (including LFS), `ident`, encoding conversion, custom merge drivers and configured external diff helpers remain unsupported.

[The conversion preview](../../src/connections/git-attributes.ts) rebuilds the staged index from exact blob identities in a fresh temporary index/object directory. It excludes disposable stat-cache fields. Native `update-index` previews the tracked stash content; a separate empty index previews nonignored untracked content. Native `checkout-index` writes only beneath a fresh scratch prefix, then the preview hashes those files and requires the original disk bytes to return exactly. This handles normal CRLF working files with LF Git blobs, including the legacy `text=auto` case where an existing CRLF index blob changes normalization. It uses the installed Git rather than duplicating Git's text/binary heuristics.

The manifest retains staged entries, raw disk entries, the stored identities that differ from disk, and a fingerprint of effective attributes/conversion configuration. `verifyStash()` compares stored content with the stash; `matchesManifest()` still requires the original raw bytes and staging. `checkoutState()` compares real files with the indexed blobs' approved checkout form, so a clean CRLF checkout does not create a stash. Preview commands have a ten-second timeout, scratch object/output inventories retain the 128 MiB limit, and all scratch writes are removed after the preview. The existing bounded durable record still limits the complete manifest before any stash.

Attribute files must be stable: their index entries match the original commit and their disk bytes match that commit's expected checkout form. New, deleted, staged or unstaged `.gitattributes` files refuse before preservation, including ignored attribute files affecting inventoried paths. Irreversible conversions also refuse before stash and name the affected path. For example, CRLF work under `eol=lf`, or mixed endings that Git cannot reconstruct, cannot satisfy byte-exact restoration.

The conversion-policy fingerprint is separate from the existing repository/check-out identities, keeping older saved reviews compatible. Recovery checks the original rules through the saved index while the PR is still checked out, so legitimate PR attributes can differ from the original rules. An external rule/configuration change stops Exit before restoration; restore the original rules and use Recover PR Checkout. Older backups without a policy record require the original nonconverting rules. Target preflight checks both committed rules and working-tree fallback, including ignored attribute files affecting target-only paths. These checks detect ordinary interference but do not lock arbitrary external Git/configuration writers. See the [research and alternatives](../research/git-attributes-prior-work.md).

## How to exercise the feature

Use the disposable fixtures:

```sh
pnpm validate
pnpm exec vitest run tests/prior-work.test.ts tests/prior-work-recovery.test.ts tests/prior-work-interference.test.ts tests/prior-work-attributes.test.ts
pnpm test:host
CRW_VSCODE_VERSION=1.141.2 pnpm test:host
```

The public manager fixture stages one version of a file, writes another version on disk, renames a file and creates a new file alongside an unrelated stash. Enter must show the exact committed PR with a clean tree; Exit must restore the original branch, staging and bytes. The installed-host fixture adds actual unsaved editor text, untitled-buffer refusal and a continuing save hook. It verifies native selections/tabs after manager recreation. Run these only through their disposable fixtures; their Git mutations never target a real user checkout.

For a manual check, install the built VSIX or relaunch the Extension Development Host and use a disposable clone with committed `* text=auto eol=lf` attributes. Stage an edit, make another edit to that same file, and add a new file. Open a verified PR overview and run **Enter PR Checkout**: the old attribute-presence refusal should be gone, and the checkout should contain the committed PR. Run **Exit Review**: the original branch, staged version, later disk edit, new file and editor state should return. For the CRLF variant, use a committed `*.ts text eol=crlf` rule and consistent CRLF bytes in the TypeScript files, leaving the attribute file itself LF. Changing the attribute file without committing it should still refuse before stash.

## Current representation and recovery limits

The first preservation path supports ordinary files with exact byte representations, reversible native LF/CRLF conversion and Git executable modes. Unsupported content transformations, unfinished attribute-file changes, unusual/non-ASCII/control-character paths, case collisions, symlinks, special index flags, sparse/split index, submodules/nested repositories, nonstandard permissions and incomplete Git operations stop before preservation. The existing exact-source reader remains available without switching. Save cancellation, unknown/untitled buffers and unstable host state retain the existing refusal behavior.

Recovery data, including the editor snapshot and full manifest, shares the existing 60,000-byte checkout-record bound. Initial preservation records must fit 56,000 bytes, reserving room for proof and bounded recovery-attempt identities before stash. Repository inventory is limited to 10,000 paths/128 MiB, including retained files removed from the index and subsequently ignored. Unsupported or oversized states refuse before stash. Git's disposable index stat cache is excluded from restoration equality.

If recovery cannot prove the recorded state, keep the saved record and protection. Resolve only the reported interference, then use **Recover PR Checkout** with Restore or Continue. A partial apply must be resolved to the exact recorded index/files; Retry does not run apply twice. Missing or moved protection and original branches require restoring the exact expected object/ref before automatic recovery can continue. Never substitute the latest ordinary stash. Review-time edits still stop Exit; their separate stash-or-stay flow belongs to #24.
