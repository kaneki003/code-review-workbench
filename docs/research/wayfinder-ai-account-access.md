# AI subscription and account access

Checked 15 October 2026 for [Establish supported AI subscription and account access](https://github.com/kaneki003/code-review-workbench/issues/4). Fact-finding only; this note does not select a provider or runtime. The owner requires an existing subscription/account route first. An API-key-only first connection does not satisfy that instruction.

## Findings that affect the design

There are documented account-based candidates. OpenAI now documents **Sign in with ChatGPT (SIWC) plan usage** for open-source/local applications, using OAuth and the public Responses API, optionally through Codex app-server. This is a **preview contract**, not a claim of unrestricted general availability. Eligible Plus/Pro accounts are documented; paid/remote applications require separate consideration. [SIWC quickstart](https://developers.openai.com/siwc/quickstart), [OSS overview](https://developers.openai.com/siwc/token-sharing-open-source), [preview limits](https://developers.openai.com/siwc/token-sharing-open-source/preview-limitations).

Gemini CLI documents Google-account sign-in, Google AI Pro/Ultra entitlements, and headless use of already cached credentials. Claude's Agent SDK explicitly bars offering third-party Claude.ai login/rate limits without prior approval. A working private token is not evidence of permission to build a subscription-powered third-party product. [Gemini authentication](https://geminicli.com/docs/get-started/authentication/), [Claude Agent SDK](https://code.claude.com/docs/en/agent-sdk/overview).

## OpenAI: exact account and preview boundary

The OSS flow starts with `client_id=dynamic_agent_client`, a persistent opaque per-host ID, PKCE, state and nonce, and a browser callback on `http://127.0.0.1:<port>/...`. Save the **issued**, account/workspace-bound client ID, validate the ID-token signature/issuer/audience/expiry/nonce, and check granted `chatgpt.tokens.use.direct` permission. This app-specific flow does not require copying another app's tokens. [Registration](https://developers.openai.com/siwc/token-sharing-open-source/sign-in).

The overview covers OSS/local apps; paid or remotely hosted apps are directed to an interest form. The quickstart says commercial partners have a limited trial, while ChatGPT plan usage is available to OSS partners and selected private clients. This establishes a plausible independent **local open-source** extension path, not blanket permission for every licensing/distribution model. Workbench has no confirmed OSS distribution decision; selected-private eligibility is unverified. Marketplace publication itself, eligibility for this repository's final license, and real-user rollout were not tested. Confirm these before making the connection a release commitment. [Overview](https://developers.openai.com/siwc/token-sharing-open-source), [quickstart](https://developers.openai.com/siwc/quickstart).

With SIWC, HTTP requests must use `store:false`, `stream:true`, explicit history in an `input` array, and instructions/developer messages. Persistent server conversations and HTTP `previous_response_id` are unavailable. Function/custom tools work; hosted file search, Code Interpreter, hosted MCP/connectors and tool search do not. Text/image/file input depends on the model; Files upload API is unavailable. App-server can still maintain **local** thread history/resume and run local shell/MCP tools. App-owned token refresh requires restarting the configured app-server process and resuming its thread. [Preview contract](https://developers.openai.com/siwc/token-sharing-open-source/preview-limitations).

Populate model choices from the account-specific `/v1/models` catalog; app-server's catalog may be bundled/cached and does not prove entitlement. Inference uses the public `/v1/responses` endpoint, not ChatGPT's private backend endpoints. A stream can fail after emitting text, including quota errors; success requires its terminal successful event. [Models/inference](https://developers.openai.com/siwc/token-sharing-open-source/models-and-inference).

Store each account registration separately and protect renewable credentials outside browser storage, logs and repository data. Refresh and revoke through the documented OAuth lifecycle. Plus's five-hour usage limit is shared across plan-using apps; Pro does not have that five-hour limit. Link to ChatGPT Settings usage/app-access controls; this is not a guarantee of unlimited inference or a predictable per-answer price. [Accounts/sessions](https://developers.openai.com/siwc/token-sharing-open-source/profiles-and-sessions).

SIWC's UI guidelines require a first-sign-in plan-use explanation, an ongoing plan-use indicator, and a Manage usage link. These are connection-specific UI obligations to reconcile with the approved design, not permission to invent app billing or silently charge API usage. Authentication denial, missing plan permission, ineligible workspace, usage exhaustion and revoked/expired credentials need distinct recoverable states. Disconnection has no push notification to the app; it must handle subsequent authorization failures. [UI guidelines](https://developers.openai.com/siwc/ui-ux-guidelines), [errors/recovery](https://developers.openai.com/siwc/token-sharing-open-source/errors-and-recovery).

## Gemini: use the client, not its private service tokens

`gemini --acp` is Google's documented stdio JSON-RPC integration for IDEs/developer tools. Its guide describes authentication, new/load session, prompt/cancel, approval-mode changes, a filesystem proxy and IDE tools exposed through MCP. Model switching is explicitly named `unstable_setSessionModel`. These capabilities make ACP more relevant than a one-shot terminal wrapper; the installed/released CLI protocol and behavior still need verification before freezing adapter interfaces. [ACP guide](https://geminicli.com/docs/cli/acp-mode/).

Gemini CLI software is Apache 2.0, but Google explicitly forbids directly accessing its backing services from third-party software with Gemini CLI OAuth. The documented ACP client talks to the actual CLI; token extraction and calling Code Assist endpoints from Workbench are not that route. This distinction is essential to the shortlist. Google-account privacy/terms vary by individual, Pro/Ultra and organizational entitlement; open-source software licensing does not grant unrestricted service access. [License/service terms](https://geminicli.com/docs/resources/tos-privacy/).

Already cached sign-in can power headless mode. Its JSONL output describes message chunks, tool calls/results, errors and a final result; exit status distinguishes general failure, invalid input and turn-limit exhaustion. Plain headless mode is insufficient for interactive Auto-style approvals: the policy engine treats `ask_user` as denial there. Evaluate ACP permission exchanges rather than using `yolo` to make a subprocess succeed. Rules support allow/deny/ask, argument/command matching, priorities and persisted user/admin policy files. An inspectable/revocable Workbench grant UI and the effect of revocation on an active process remain to prove. [Headless](https://geminicli.com/docs/cli/headless/), [policy engine](https://geminicli.com/docs/reference/policy-engine/).

Published daily maxima currently distinguish Google-account individuals (1,000 requests), AI Pro (1,500) and AI Ultra (2,000); rate limits, demand and model availability still apply. These are model requests, not a promise of that many complete review questions. Google AI Plus and several Workspace AI plans are explicitly excluded from the listed supported tiers. Usage/remaining limits can be checked through the documented CLI commands; API/Vertex pay-as-you-go is a different deliberate connection. [Quota/pricing](https://geminicli.com/docs/resources/quota-and-pricing/).

Sessions save conversation/tool history locally under a project hash, support exact-ID resume and deletion, and default to 30-day cleanup. A repository-level cache is not automatically PR isolation; the adapter must map the exact provider session to the Workbench PR and clear policy. Do not resume whichever session happens to be latest. The initial SDK package appears in official release notes, but no stable, account-compatible embeddable SDK contract was verified here; ACP/CLI has the clearer documented product integration surface. [Sessions](https://geminicli.com/docs/cli/session-management/), [release notes](https://geminicli.com/docs/changelogs/).

## Runtime and implementation evidence

Local read-only checks found Codex CLI `0.162.1` at `/Users/saksham/.local/bin/codex`. Its help exposes app-server stdio/Unix/WebSocket transports, generated TypeScript/schema commands and non-interactive JSON events, resume, ephemeral execution and output schema. Help labels app-server experimental. No authentication, provider install, secret read, account-status request or inference was performed. These observations establish an installed interface, not compatibility on users' machines.

Codex documentation positions app-server for rich clients with authentication/history/approvals/events, and the SDK for automation. The CLI reference labels app-server experimental; its WebSocket transport is explicitly unsupported for production. Native CLI/IDE auth and OS credential storage are provider-owned; SIWC credentials are app-owned. [App-server](https://learn.chatgpt.com/docs/app-server), [CLI maturity](https://learn.chatgpt.com/docs/cli/reference), [SDK](https://learn.chatgpt.com/docs/codex-sdk), [authentication](https://learn.chatgpt.com/docs/auth).

Gemini's documented installation prerequisites are Node 20+, network access and a supported shell; its current supported-OS list names macOS 15+, Windows 11 24H2+ and Ubuntu 20.04+. An extension using a separately installed CLI must diagnose those prerequisites. Do not assume VS Code's embedded Node is a supported standalone CLI runtime or silently install a provider. [Installation](https://geminicli.com/docs/get-started/installation/).

Codex documents standalone installation and platform-specific sandboxes for macOS/Linux/native Windows/WSL2. Native Windows and WSL must not be treated as the same process/path environment. Direct SIWC HTTP avoids a CLI binary prerequisite but supplies no local execution sandbox. Bundling versus requiring a separately installed provider, exact redistributed-package licenses/notices, version pinning, update handling and Marketplace review remain implementation decisions. TypeScript/Node can drive the documented HTTP or stdio surfaces; these facts do not select the extension UI framework. [CLI](https://learn.chatgpt.com/docs/codex/cli), [platform security](https://learn.chatgpt.com/docs/agent-approvals-security).

## Capability implications, separated from architecture choices

| Requirement | Documented evidence / remaining work |
| --- | --- |
| Streaming, Stop, tool activity | Codex app-server emits item deltas and terminal turn states, supports `turn/interrupt`, command/file approvals and session/prefix grants. Persist partial chunks before marking interruption; confirm subprocess/tool termination separately. `thread/revert` changes supported thread history, not filesystem effects. [Protocol](https://learn.chatgpt.com/docs/app-server). Gemini ACP documents cancel/session control; headless exposes tool/result events. Verify child-process cancellation and partial retention in the spike. |
| Retry without duplicated questions | No universal exactly-once retry contract was established. Keep Workbench's user-message identity and attempt state locally. Direct SIWC can reconstruct explicit history; provider thread replay/revert requires route-specific handling. Do not blindly resend an uncertain completed tool action or append another visible user question. |
| Auto-style command behavior | Codex's workspace-write/on-request mode allows routine workspace work and pauses outside policy; this is distinct from automatic review of approvals. Its sandbox implementations differ by OS. Gemini has policies and ACP approval modes; headless asks are denied. Native mechanisms are building blocks, not proof that Workbench's saved grants, revocation and all process descendants are controlled. [Codex permissions](https://learn.chatgpt.com/docs/agent-approvals-security), [Gemini policies](https://geminicli.com/docs/reference/policy-engine/). |
| Source attribution and structured suggestions | Provider-generated citations are not a source-freshness guarantee. Workbench must validate source IDs/paths/ranges against captured evidence and validate any suggestion schema. Codex exposes per-turn output schema; account-route/model support still needs a spike. No verified cross-provider schema/citation parity is claimed. |
| Text/PDF attachments | Keep the approved text-only PDF scope. Workbench can extract text locally with page/partial-read provenance and send bounded text. SIWC model-dependent file input does not imply Files-upload support or app-server PDF RPC support. Gemini ACP's exact attachment mapping remains unverified. An unreadable PDF must stay visibly unreadable. |
| Context limits | Limits depend on the selected model, entitlement and harness. No universal PR-size threshold or useful-context benchmark was established. Bound reads/search/output and summarize with references; expose omitted/truncated material. Confirm each selected model's documented window during implementation instead of hard-coding a cross-provider number. |

The following are product-preserving architecture implications, **not provider claims or selected implementation**: retain the canonical PR conversation, decisions, guidance, attachments, source revisions and generation attempts on device; scope native session IDs to one PR/account/provider; apply current-review > repository > personal guidance explicitly; load repository context incrementally; retrieve other PRs only after explicit reference; mark source-derived material stale after Sync; record the active model, require deliberate provider switching and keep manual review available after AI failure. Provider auto-memory, skills, project config, plugins and MCP discovery must be inspected/controlled so they do not silently import unrelated review memory or executable add-ons. The product boundaries come from [FR13–FR19 and scope](../product/PRD.md), not provider defaults.

Keep GitHub publication/merge capabilities outside the model tool registry. That alone is insufficient if an unrestricted shell can reach `gh`, Git push or a credentialed network client. The command service must enforce the publication boundary and keep GitHub credentials out of the AI child environment. Separate bounded source reads/search from permissioned commands, preserve generated output/source-changing command behavior from FR15, and validate that configured MCP/tools cannot bypass the boundary. Direct HTTP requires app-owned execution controls; adopting a CLI requires proving its policy/config isolation. This control design remains unresolved.

Claude's SDK has session/tool/permission features, but those features do not remove its subscription-auth restriction. Its headless bare mode skips automatic project hooks/MCP/skills but explicitly does **not** use subscription login. Therefore it cannot serve as a subscription-first configuration-isolation workaround. [SDK overview](https://code.claude.com/docs/en/agent-sdk/overview), [programmatic/bare mode](https://code.claude.com/docs/en/headless).

## Viable-first-connection shortlist

1. **Gemini CLI through documented ACP** is an account-first integration candidate with an explicit editor protocol. Confirm real account eligibility, protocol version, permission UI/grants, context isolation and OS packaging before selecting it.
2. **SIWC + direct Responses or app-server** is conditional on resolving Workbench's distribution/eligibility and accepting the preview contract. Direct HTTP maximizes app control of conversation/tools; app-server offers an agent harness plus another process/protocol dependency. This note does not rank practical quality or choose between them.

Unapproved Claude subscription embedding and arbitrary provider-token reuse are excluded. If neither shortlisted route can pass eligibility and a working spike, subscription-first AI is blocked pending a supported provider agreement/route; it is not resolved by silently choosing API billing.

## Remaining fact checks and decisions

- Compare SIWC direct Responses versus SIWC + app-server against tools, permissions, Stop, session retention and packaging. This is an architecture decision, not settled by account compatibility alone.
- Verify Gemini's ACP/session/permission behavior in the released binary before selecting it. Cached-account headless use and ACP are documented; direct use of its backing services with CLI OAuth is prohibited.
- Confirm intended OSS/distribution model and account eligibility. Do not quietly replace an unavailable subscription route with API billing.
- Use a no-publication provider spike before rollout: real account sign-in, one streamed question, interrupted partial output, resumed PR context, quota/auth failure, permission denial/revocation, then packaging checks on all target desktops. These require owner-authorized account use later; none was performed for this note.

Practical quality, useful context size for large/mixed-language PRs, speed, account availability and the exact cost of an interaction remain unmeasured. This note supplies compatibility evidence, not benchmark claims or a provider choice.
